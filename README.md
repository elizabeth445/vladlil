# Владислав та Лілія — приглашение

Next.js App Router, React, TypeScript, GSAP. Интерфейс на украинском, локальные шрифты и акварельные иллюстрации. Три формы отправляются напрямую в личный Telegram организаторов: RSVP, анкета Владислава, анкета Лілії.

## Настройка Telegram

1. Откройте официальный [BotFather](https://t.me/BotFather), отправьте /newbot и создайте бота. Сохраните выданный токен в серверных переменных, не в исходниках. Если токен стал публичным, замените его через BotFather перед использованием для реальных гостей.
2. Скопируйте .env.example в .env.local и заполните TELEGRAM_BOT_TOKEN. Этот файл исключён из Git. Не передавайте токен в аргументах команд, адресной строке браузера, клиентском коде или переменных NEXT_PUBLIC_.
3. Откройте созданного бота в Telegram и отправьте ему /start с аккаунта организатора.
4. Выполните npm run telegram:chat-id. Утилита делает один getUpdates с timeout=0, печатает только ID и имя личных чатов, в которых отправлен /start, и завершается. Токен и тексты переписки не печатаются. Она не запускает polling, не подтверждает очередь через offset и не меняет webhook. Если чатов несколько, выберите свой; если обновлений нет, отправьте новый /start и повторите команду. Если уже установлен webhook, утилита сообщит об этом, не удаляя его.
5. Добавьте числовой TELEGRAM_CHAT_ID в .env.local. Это ID личного чата организатора, а не имя бота. Перезапустите локальный сервер.

Команды:

~~~sh
source ~/.codex/bin/frontend-env.sh # только если Node/npm отсутствуют в PATH
npm ci
npm run telegram:chat-id
npm run dev
~~~

## Vercel Production

В проекте vladlil откройте Settings → Environment Variables. Добавьте TELEGRAM_BOT_TOKEN и TELEGRAM_CHAT_ID для Production. Для токена выберите Sensitive; обе переменные серверные, без NEXT_PUBLIC_. После изменения переменных запустите новое production-развёртывание (Redeploy или push в main). Старое развёртывание не получает новые настройки автоматически. Preview и Development настраиваются отдельно; не подключайте тестовые ветки к рабочему чату без необходимости.

APP_ORIGIN необязателен: это точный origin сайта (например https://vladlil.vercel.app), без завершающего слеша. По умолчанию проверяется origin текущего запроса. Старая NEXT_PUBLIC_SUBMISSIONS_ENABLED больше не используется, её можно удалить из настроек.

Дополнительный хостинг, БД, Supabase, webhook, сервер бота и панель администратора не нужны. Старые /admin, /api/admin/*, /api/letters и /api/rsvp удалены; прежние локальные файлы .data не удаляются и не публикуются.

## Как проверить получение

Откройте сайт, затем заполните и отправьте RSVP и обе анкеты. Для проверки используйте имя «ТЕСТ — Марія» и вымышленные ответы. Должны прийти три уведомления на украинском с типом формы, именем, всеми ответами, временем Europe/Kyiv и тематическими значками. Длинная анкета придёт несколькими пронумерованными сообщениями с сохранением порядка вопросов. Все части должны быть подтверждены Telegram до показа успеха на сайте.

Сначала /start даёт боту возможность написать вам; сам бот на команды не отвечает. Уведомления появляются после отправки формы на сайте. Письма отправляются в личный чат организатора с ботом, не всем пользователям бота.

## Доставка и ограничения

/api/submit принимает JSON только с того же origin, проверяет Zod-схему, honeypot, минимальное время заполнения, длины полей и тело до 32 КБ. У Telegram sendMessage лимит 4096 символов; отправляем части короче 4000 UTF-16 единиц без HTML/Markdown и предпросмотра ссылок. Между частями выдерживается короткий интервал. Браузер блокирует повторные нажатия на время запроса. Таймауты и ошибки Telegram не показываются как успех, поля и независимые localStorage-черновики сохраняются.

Без постоянного хранилища невозможно гарантировать идемпотентность или ровно одну доставку: потерянный ответ может следовать за доставленным сообщением, а часть длинного письма может успеть прийти до ошибки. Автоматических повторов нет; сайт предупреждает о неопределённой/частичной доставке. Перед ручным повтором сверьтесь с организатором; имя, время и одинаковые ответы помогают распознать дубликат. Встроенного «глобального» in-memory rate limit нет: он ненадёжен между Vercel-инстансами. Для усиленной защиты публичной ссылки можно отдельно настроить правила Vercel Firewall.

## Проверки

~~~sh
npm run lint
npm run typecheck
npm test
npm run build
~~~

Автотесты Telegram используют подменённый fetch, а браузерные тесты — перехват /api/submit, чтобы не спамить реальному организатору. Они проверяют три типа форм, ошибки, блокировку повторных кликов, длину/порядок частей и подтверждение доставки. Реальную доставку можно утверждать только после отдельной отправки с рабочими серверными настройками. Браузерные проверки включают iPhone WebKit, responsive и reduced motion.

## Визуальные материалы

`public/art/` содержит оптимизированные локальные WebP:

- `lion.webp`, `kitten.webp` — оригинальные акварельные персонажи, созданные встроенным ImageGen по референсам пользователя.
- `celebration-frame.webp`, `celebration-frame-mobile.webp` — оригинальные акварельные обрамления, разная композиция для desktop и mobile.
- `franco.webp` — фасад с официального сайта [FRANCO](https://franco.net.ua/). Источник: `https://franco.net.ua/wp-content/themes/franc/img/a1c9d71e-3ae9-4f6d-854a-b533e3a483cd-2.jpg`.

Промпты ImageGen: акварельный львёнок с короной, голубым бантом, машинкой и мячом; пушистый кремовый котёнок с розовым бантом, цветами и бабочкой; прозрачные рамки с голубыми и розовыми шарами, облаками и цветами, пустым центром для HTML-текста. Использован встроенный ImageGen, прозрачность сохранена.

Shantell Sans и Onest размещаются локально через Fontsource; украинские І, Ї, Є, Ґ включены в кириллические диапазоны. Для анимаций используется только GSAP и CSS, без второго цикла smooth scrolling.
